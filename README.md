# figly-content

The Figly content catalog — `content.json` and its `content.json.sha256`
integrity hash — served live to the Figly Android TV app and web dashboard.

## How it's served

This repo is deployed via **GitHub Pages** (branch `main`, root directory):

```
https://figly-app.github.io/figly-content/content.json
https://figly-app.github.io/figly-content/content.json.sha256
```

Both apps fetch directly from that URL and verify the downloaded file against
the SHA-256 hash before using it.

**Not a jsDelivr mirror.** This repo was previously accessed indirectly via
jsDelivr's GitHub-file CDN proxy (`cdn.jsdelivr.net/gh/figly-app/figly-content@main/...`).
jsDelivr enforces a hard 20MB cap on files it proxies — `content.json` exceeded
that around 2026-07-01, and jsDelivr silently returned a 403 on every fetch on
both platforms for weeks before anyone noticed. The fix (Task #236 in the main
[figly](https://github.com/figly-app/figly) repo) moved serving to this repo's
own native GitHub Pages site, which has no comparable per-file size limit.

## How it gets updated

`content.json` is generated by the enrichment pipeline in the main `figly`
repo (`enrichment/enrich.py`), which opens a weekly PR against
`figly/content/content.json`. Once that PR merges to `figly`'s `main` branch,
a CI job (`figly/.github/workflows/sync-content-to-pages.yml`) automatically
copies the updated file here and pushes to this repo's `main` branch, which
GitHub Pages then redeploys.

**Do not push to this repo by hand.** Regenerate the catalog via
`enrichment/enrich.py` in the main repo instead — a hand-edited file here will
be silently overwritten by the next automated sync, and (more importantly)
won't match the catalog's own SHA-256 hash file if edited without
regenerating it.
